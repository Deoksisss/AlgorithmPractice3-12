# Лабораторная работа №3 — стек, очередь и выражения

Консольная утилита на C# для исследования линейных структур данных,
вычисления постфиксных выражений и перевода инфиксной записи в постфиксную.
Интерфейс оформлен спокойно: тёмно-серые рамки, серый текст, голубой акцент
и цветные статусы только там, где это помогает читать результат.

## Быстрый запуск

Требуется .NET 10 SDK.

```powershell
dotnet run
```

Запуск из корня проекта. Папки с данными и отчётами определяются автоматически
(работает и при запуске из `bin/Debug/net10.0`). Решение для IDE:
`StackQueueLab.slnx`.

Диагностика всех структур, алгоритмов и тестовых файлов:

```powershell
dotnet run -- --self-test
```

Стресс-файлы по умолчанию пропускаются, чтобы проверка была быстрой.
Их можно включить отдельно:

```powershell
dotnet run -- --self-test --include-extreme
```

Проверка дополнительных заданий с `CustomLinkedList`:

```powershell
dotnet run -- --linked-list-test
```

Интерактивный графический визуализатор на Avalonia:

```powershell
dotnet run --project DataStructuresVisualizer/DataStructuresVisualizer.csproj
```

## Что реализовано

| Блок | Реализация |
|---|---|
| Стек | `LinkedStack<T>` на собственном односвязном списке: `Push`, `Pop`, `Top`, `isEmpty`, `Print` |
| Очередь | `LinkedQueue<T>` на собственном связном списке и адаптер стандартного `Queue<T>` |
| Операции 1–5 | единый исполнитель `OperationSetRunner` через интерфейс `ILinearCollection` |
| Постфикс | `PostfixEvaluator` на собственном стеке, `PostfixValidator`, оценка `O(n)` |
| Инфикс → постфикс | `InfixToPostfixConverter` (shunting-yard) с приоритетами в стеке |
| Отчёты | CSV в `output`, имя `<исходный_файл>-<дата_время>.csv` |
| Сравнение очередей | отдельный отчёт по разной длине и разному составу операций |
| CustomLinkedList | задания 1–8 для односвязного списка и автономные проверки |
| Меню «Алгоритмы связного списка» | выбор заданий, генерация или ручной ввод, цветной результат |

## Форматы файлов

### Операции стека и очереди

Одна строка — один набор. Токены разделяются пробелами:

```text
3 4 1,56 1,7 1,cat 2 5 4
```

* `1,значение` — добавить;
* `2` — удалить;
* `3` — посмотреть первый элемент / вершину;
* `4` — проверить пустоту;
* `5` — напечатать.

Операция `2` или `3` на пустой структуре не является ошибкой файла: в журнале
будет показано «пусто», операция пропускается. А вот неизвестный токен,
`1` без значения, запятая внутри значения и другие лишние данные приводят к
отклонению всего файла. Пользователь увидит строку и токен, затем снова
попадёт в выбор файла.

### Постфиксные выражения

Одна строка — одно выражение:

```text
4 2 + 3 *
2 3 ^ 1 -
9 sqrt 2 +
0.5 sin 2 *
```

Поддерживаются числа, `+`, `-`, `*`, `/`, `:`, `^`, `ln`, `cos`, `sin`,
`sqrt`, а также `u-` для унарного минуса после конвертации.
`ln` — натуральный логарифм, `cos`/`sin` принимают радианы.

### Инфиксные выражения

```text
2+2
(2+3)*4
sin(0.5)+cos(0.5)
sqrt(9)+2^3
2^3^2
-2^2
```

Функции требуют скобок. Приоритеты: `+ -` < `* / :` < `^` < унарный минус;
`^` правоассоциативен. Приоритеты учитываются стеком в shunting-yard.

## Сценарии

### Стек

1. Главное меню → `1`.
2. Выберите файл из `StackInput` (если файлов несколько, отображается список).
3. Каждая операция печатается отдельно.
4. После набора выводится время и визуальный разделитель.
5. После всех наборов — сообщение о завершении, сводка и CSV.

### Очередь

1. Главное меню → `2`.
2. `1` — выполнить файл обеими реализациями; `2` — сравнительный отчёт.

Сравнительный отчёт автоматически обрабатывает все корректные файлы
`QueueInput` и показывает:

* файлы разной длины;
* файлы одинаковой длины с разным составом (`push`, `read`, `mixed`);
* расхождение по времени и максимальное отношение стандартной очереди
  к связанной;
* CSV `output/queue_benchmark_<дата_время>.csv`.

### Постфикс

Выберите файл из `PostfixInput`. Для каждого выражения выводятся:

```text
[   1/1000] строка 1: 4 2 + 3 *
         = 18
         5 операций : 0.0031 мс : O(n), память O(n)
```

CSV: `количество операций;время (мс);сложность`.

### Инфикс → постфикс

* `1` — ввести имя файла и формулу; формула сохраняется в `InfixInput`,
  затем показываются постфиксная запись, значение, время и сложность;
* `2` — обработать готовый файл выражений из `InfixInput`.

В обоих случаях создаётся CSV в `output`.

## Кнопка «назад»

В каждом меню и в списке файлов есть `0 — назад`. Список файлов также
обновляется клавишей `R`; для продолжения после результата — `Enter`.

### Стресс-файлы «больше минуты»

Это файлы с **1000 наборами/выражениями**, но каждая строка длинная, а
количество операций и их состав отличаются от строки к строке. Для `push`
используются разные числа и слова, поэтому структура не заполняется одним и
тем же элементом.

| Файл | Что внутри |
|---|---|
| `StackInput/stack_EXTREME_1000_sets_3000000_ops.txt` | 1000 наборов, 3 000 000 операций, длина наборов примерно 1500–4400 |
| `QueueInput/queue_EXTREME_1000_sets_1500000_ops.txt` | 1000 наборов, 1 500 000 операций; две реализации дают около 3 000 000 строк вывода |
| `PostfixInput/postfix_EXTREME_1000_expressions_3M_tokens.txt` | 1000 выражений, около 3 000 000 токенов, разная длина и разные операции |
| `InfixInput/infix_EXTREME_1000_expressions_3M_tokens.txt` | 1000 выражений, около 3 000 000 токенов, разная длина и разные операции |

Для стресс-файлов:

* стек и очередь печатают каждую операцию;
* в наборах есть `Push`, `Pop`, `Top`, `isEmpty`, `Print`, причём их
  количество и порядок меняются;
* `Push` получает разные значения: числа, отрицательные числа, дроби и слова;
* постфикс выполняет пошаговую трассировку «токен → глубина стека»;
* инфикс выводит постфиксную запись по одному токену на строку;
* в конце показывается **полное время с выводом**, отдельно от времени
  алгоритма, которое попадает в CSV;
* стресс-файлы не включаются в автоматический сравнительный отчёт очереди,
  чтобы не смешивать минутный вывод с обычными замерами.

Полное время зависит от терминала. Если нужно ещё больше, параметры
генератора можно увеличить:

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\GenerateStressData.ps1 `
  -StackOperations 5000000 -QueueOperations 2500000 `
  -ExpressionTokens 5000000 -SetCount 1000
```

Обычные тестовые данные воспроизводятся скриптом:

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\GenerateTestData.ps1
```

## Дополнительные задания с `CustomLinkedList`

Список и проверки находятся здесь:

```text
Core/Structures/CustomLinkedList.cs
Diagnostics/LinkedListSelfTestRunner.cs
Services/LinkedListTaskService.cs
UI/Controllers/LinkedListLabController.cs
```

В главном меню добавлен пункт **«Алгоритмы связного списка»**. Для каждого
задания можно выбрать:

1. случайные значения — список из 7–25 чисел от 0 до 999;
2. ручной ввод — целые числа через пробел или запятую.

Для заданий с параметрами дополнительно запрашиваются `x`, `E`, `F`.
Перед выполнением показывается исходный список, после выполнения —
результат. Голубым цветом выделяются только элементы, реально изменившие
своё положение. Элементы, сдвинутые из-за чужой вставки, удаления или
переноса другого элемента, цветом не выделяются.

Реализованные методы:

| Задание | Методы |
|---|---|
| 1. Переворот | `Reverse` |
| 2. Перенос крайнего элемента | `MoveLastToFront`, `MoveFirstToLast` |
| 3. Количество различных | `CountDistinct` |
| 4. Удаление неуникальных | `RemoveNonUnique` |
| 5. Вставка списка после `x` | `InsertSelfAfter` |
| 6. Вставка в упорядоченный список | `InsertSorted` |
| 7. Удаление всех `e` | `RemoveAll` |
| 8. Вставка `f` перед `e` | `InsertBefore` |

Запуск проверок:

```powershell
dotnet run -- --linked-list-test
```

Тесты проверяют пустой список, один элемент, начало, середину, конец,
отсутствие элемента и корректность `Count` после операций.

## Avalonia-визуализатор

Отдельный проект:

```text
DataStructuresVisualizer/
```

Запуск:

```powershell
dotnet run --project DataStructuresVisualizer/DataStructuresVisualizer.csproj
```

Интерфейс содержит три вкладки:

1. **Стек: лабиринт DFS**
   - случайный или ручной лабиринт;
   - символы `#`, `.`, `S`, `E`;
   - плавная анимация Push/Pop, обхода, тупиков и итогового пути;
   - справа показывается текущее состояние стека.
2. **Очередь: банк / МФЦ**
   - случайная смена или ручные клиенты в формате
     `Имя, минута прихода, минуты обслуживания`;
   - анимированная очередь FIFO и рабочее место кассира;
   - живая статистика: всего клиентов, обслужено, ожидание, загрузка, простой.
3. **Дерево: арифметическое выражение**
   - случайное или ручное выражение;
   - перевод в постфиксную запись через стек;
   - построение бинарного дерева;
   - пошаговая подсветка пост-порядкового вычисления;
   - собственная LRU-хеш-таблица для уже вычисленных выражений:
     если подвыражение вроде `2 3 +` встречалось ранее, результат берется из
     кэша, а его ветвь повторно не вычисляется;
   - статистика кэша: размер, попадания, промахи и вытеснения;
   - результат выражения.

В каждом разделе есть кнопка запуска, остановка и сброс. Проект использует
Avalonia 11.1, темный Fluent-стиль, переходы `BrushTransition` и
`DoubleTransition` для анимации цвета и положения элементов.

## Замеры и отчёты

* Время чтения и разбора файла измеряется отдельно.
* Каждый набор сначала выполняется в «тихом» режиме для чистого замера,
  затем проигрывается ещё раз для пооперационного вывода. Форматирование
  журнала и консольный вывод не входят в измеренное время.
* В CSV для стека: `Количество операций;Время выполнения (мс)`.
* В CSV для очереди: количество операций и время обеих реализаций.
* В CSV для постфикса: количество операций, время и оценка сложности.
* В CSV сравнения очередей: файл, набор, операции, обе реализации, разница,
  отношение.
* Если файл отчёта с таким именем уже существует, добавляется суффикс `-2`,
  `-3` и т.д.
