# Лабораторная работа №3 — план и архитектура

## 1. Цель

Консольная утилита на C# для демонстрации работы:

1. стека на собственном связном списке;
2. очереди на собственном связном списке и на стандартном `Queue<T>`;
3. вычисления постфиксных выражений с оценкой сложности;
4. перевода инфиксной записи в постфиксную (алгоритм Дейкстры / shunting-yard);
5. замеров времени, сравнения реализаций и выгрузки отчётов в CSV.

Интерфейс — спокойный, без «радужных» цветов: тёмно-серые рамки, серый текст,
приглушённый голубой акцент, зелёный/жёлтый/красный только для статусов.

## 3. Абстрактные интерфейсы

### `IStackADT<T>`

Контракт стека: `Push`, `Pop`, `Peek` (Top), `IsEmpty`, `Count`, `Snapshot`.
Реализация — `LinkedStack<T>` на собственных узлах `StackNode<T>`.

### `IQueueADT<T>`

Контракт очереди: `Enqueue`, `Dequeue`, `Peek`, `IsEmpty`, `Count`, `Snapshot`.
Реализации:

* `LinkedQueue<T>` — собственный связный список с `head`/`tail`;
* `SystemQueueAdapter<T>` — обёртка над стандартным `Queue<T>`.

Это позволяет прогнать **один и тот же набор операций** через обе реализации.

### `ILinearCollection`

Единый адаптер для исполнителя операций `1–5`:

```text
Add / Remove / Peek / IsEmpty / Snapshot / DisplayName
```

Стек и очередь отличаются только названиями операций в журнале. Благодаря
интерфейсу `OperationSetRunner` не знает, с чем работает: со стеком, связанной
очередью или стандартным `Queue<T>`.

### `IExpressionConverter`

`string Convert(string infix)` — перевод инфиксной записи в постфиксную.
Реализация `InfixToPostfixConverter` использует собственный `LinkedStack<string>`
и приоритеты операций.

### `IPostfixEvaluator`

`double Evaluate(string postfix)` — вычисление постфиксного выражения.
Реализация `PostfixEvaluator` использует собственный `LinkedStack<double>`.

## 4. Форматы данных

### Наборы операций (стек / очередь)

Каждая непустая строка файла — отдельный набор. Токены разделены пробелами:

* `1,значение` — добавление;
* `2` — удаление;
* `3` — просмотр первого элемента / вершины;
* `4` — проверка на пустоту;
* `5` — печать.

Любой другой токен, `1` без значения, пустое значение и т.п. считаются
лишней/некорректной информацией. Такой файл не выполняется: пользователю
показывается строка и токен ошибки, затем снова открывается выбор файла.

### Постфиксные выражения

Одна строка — одно выражение. Поддерживаются числа (в том числе дробные),
`+`, `-`, `*`, `/`, `:`, `^`, `ln`, `cos`, `sin`, `sqrt`. Скобки в постфиксной
записи допускаются как нейтральные разделители (на случай «лишних» символов),
но на результат не влияют. Унарный минус, полученный при конвертации,
обозначается токеном `u-` и также поддерживается вычислителем.

### Инфиксные выражения

Пользователь вводит имя файла и формулу. Файл сохраняется в `InfixInput`.
Поддерживаются те же операции, скобки, унарный минус/плюс, функции с
обязательными скобками: `sin(0.5)`, `sqrt(9)`, `ln(2)`.

## 5. Алгоритмы

### Стек

Односвязный список, вершина — `head`. `Push` добавляет узел в начало, `Pop`
снимает `head`. Все операции, кроме `Print`, — `O(1)`; `Print` — `O(n)`.

### Очередь на связном списке

Односвязный список с указателями `head` и `tail`: `Enqueue` — в `tail`,
`Dequeue` — из `head`. Все основные операции — `O(1)`.

### Постфиксное вычисление

1. Читаем токены слева направо.
2. Число — в стек.
3. Бинарная операция — снимаем два числа, применяем, кладём результат.
4. Функция — снимаем одно число, применяем, кладём результат.
5. В конце в стеке ровно один результат.

Время — `O(n)`, дополнительная память — `O(n)` (глубина стека).
Для каждого выражения выводится:

```text
количество операций : время (мс) : расчёт сложности
```

### Инфикс → постфикс

Алгоритм shunting-yard:

* числа сразу попадают в выход;
* функции и `(` — в стек;
* `)` выталкивает операторы до `(`;
* оператор выталкивает из стека операторы с большим/равным приоритетом
  (для правоассоциативного `^` — только с большим);
* приоритеты: `+ -` = 1, `* / :` = 2, `^` = 3 (справа налево),
  унарный минус = 4.

Приоритеты хранятся в стеке, поэтому требование «учитывать приоритет с
помощью стека» выполняется непосредственно алгоритмом.

## 6. Замеры и отчёты

* Чтение и разбор файла замеряются отдельно (`Stopwatch`).
* Каждый набор выполняется с собственным замером; журнал операций
  формируется в памяти, затем печатается, чтобы консольный ввод-вывод не
  искажал время алгоритма.
* После каждого набора печатается время; между наборами — визуальный разделитель.
* После всех наборов — сообщение о завершении, сводка и путь к CSV.
* CSV пишется в `output` с именем
  `<исходный_файл>-<дата_время_старта>.csv`.
* Для очереди дополнительно создаётся сравнительный отчёт:
  `queue_benchmark_<дата_время>.csv` с временами связанной очереди и
  стандартного `Queue<T>`, разницей и отношением.
* Тестовые наборы очереди специально включают:
  1. разную длину (`10`, `100`, `1000` операций в наборе);
  2. одинаковую длину с разным составом (`push`-heavy, `read`-heavy,
     `mixed`) для заметного расхождения по времени.

## 7. Стресс-тесты с длинными наборами

Для проверки полного времени с выводом добавлены EXTREME-файлы, в каждом из
которых около 1000 наборов/выражений. Длина строк и состав операций
различаются, а не повторяются от строки к строке:

* стек — 1000 наборов, всего 3 000 000 операций, в среднем 1500–4400
  операций на набор; `push` получает разные числа и слова;
* очередь — 1000 наборов, всего 1 500 000 операций (около 3 000 000 строк
  вывода на две реализации);
* постфикс — 1000 выражений примерно на 3 000 000 токенов, разные операции
  и разная длина;
* инфикс — 1000 выражений примерно на 3 000 000 токенов, разные операции
  и разная длина.

Обычный замер алгоритма и полное время с выводом показываются отдельно:
CSV хранит алгоритмическое время, экран — ещё и полное. Файлы генерируются
скриптом `tools/GenerateStressData.ps1` с настраиваемыми размерами.
Список файлов в меню строится лениво: содержимое разбирается только после
выбора, поэтому наличие стресс-файлов не замедляет обычную навигацию.

## 8. Пользовательские сценарии

```text
Главное меню
├── Стек
│   └── выбор файла → выполнение → CSV
├── Очередь
│   ├── выбор файла → выполнение обеими реализациями → CSV
│   └── сравнительный анализ всех файлов → CSV
├── Постфиксные выражения
│   └── выбор файла → вычисление → сложность → CSV
└── Инфикс → постфикс
    ├── ручной ввод и сохранение в InfixInput
    └── обработка файла выражений → CSV
```

В каждом подменю есть пункт `0 — Назад`; выбор файла также можно отменить.
При отсутствии файлов выводится путь к папке и предложение вернуться назад.
